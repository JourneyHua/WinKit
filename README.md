# WinKit 系统管家

Windows 11 上的一站式轻量系统管家：**体检与维护（一键体检报告 + 每周自动维护）**、**系统概览**、**磁盘健康**、**环境变量与 PATH**、**右键菜单**、**此电脑显示项**、**资源管理器左侧导航栏与任务栏/通知区域**、**应用管理（卸载/更新/运行库/系统工具库/卸载残留清理，含 Scoop 包）**、**驱动管理（备份卸载与更新）**、**启动与服务（自启/服务/计划任务）**、**系统清理（缓存清理与大文件扫描）**、**系统调优与百宝箱（Win11 开关/端口诊断/深层面板直达）**、**文件占用解锁**、**文件与文件夹对比**、**重复文件检测**、**默认打开方式**、**事件日志诊断**、**Windows 更新管理**、**网络诊断**、**注册表体检**。
支持快照的注册表与轻量文件改动会先保存备份，驱动卸载前自动导出驱动包；结束进程、缓存清理及外部安装/卸载不属于快照撤销范围。不装后台服务。

仓库：https://github.com/JourneyHua/WinKit

## 能力边界（先读这段，避免预期落空）

| 你能做的 | 你做不到的（系统限制，不是 bug） |
|---|---|
| 一屏看清系统版本、CPU/内存/显卡、各卷占用、待重启、Defender/防火墙/安全启动状态 | 读取需要硬件驱动的实时传感器数据（温度、风扇转速）——那要内核驱动 |
| 屏蔽第三方软件塞进 Win11 一级菜单的项（两层深度屏蔽），或一键全局切回经典菜单 | 删掉一级菜单里的**内置项**（复制/粘贴/重命名/共享/发送到/删除/属性）——微软没有开放接口 |
| 禁用/删除/改名经典菜单里的任意项（8 个位置域） | 给右键菜单拖拽排序 |
| 隐藏此电脑里的用户文件夹、系统节点、任意盘符 | 改盘符字母 |
| 关闭软件钉在左侧导航栏的节点（iCloud Photos、WPS 云盘、应用宝等），彻底清理自动重建的顽固节点 | 把任意 exe 钉成导航栏一级图标（要写自定义 CLSID，非官方） |
| 增删快速访问固定项、调整顺序、开关导航窗格选项 | 给右键菜单拖拽排序 |
| 列出任务栏固定项并取消固定、显示/隐藏通知区域图标、清理指向已删除程序的失效记录 | 把程序**固定到任务栏**（Win11 没有公开入口），因此也无法调整任务栏顺序 |
| 卸载传统桌面软件与商店/打包应用、清理卸载注册表残留、通过系统内置 `winget` 检查并一键更新软件 | 强制静默卸载没有提供静默参数的第三方安装器 |
| 拖入文件夹或快捷方式反查卸载入口、扫描目录/快捷方式/服务/计划任务/启动项/文件关联六类残留并一键清理（进回收站 + 可撤销） | 精确判断「这个目录属于哪个软件」——同名/发布者名相同的目录只能列为「可能」，需人工确认 |
| 按类别管理第三方驱动包（`oem*.inf`）、卸载前自动备份驱动包、通过 Windows Update 或本地 `.inf` 更新驱动 | 删除微软系统内置的核心基础驱动 |
| 对比两个文件夹/文件的差异（大小、时间、可选哈希），校验备份完整性 | 跨机器同步或三方合并（这是比对，不是同步工具） |
| 按内容查找重复文件并按组清理（进回收站） | 恢复回收站里被其它程序删掉的文件 |
| 查看每个扩展名当前关联到哪个程序、跳转系统设置更改、清理失效关联 | 绕过 `UserChoice` 哈希保护直接改默认程序（系统会判定篡改并重置） |
| 读 S.M.A.R.T. 预测失败位、SSD 磨损度、温度、通电时长 | 读机械硬盘的实时转速或环境温度传感器（要厂商专用驱动） |
| 可视化编辑用户/系统环境变量与 PATH 顺序 | 让已经在运行的程序立刻拿到新环境变量（Windows 机制限制，需重启进程） |
| 生成体检报告、注册每周自动维护任务 | 让维护任务在睡眠/关机时也照常运行（Windows 计划任务本身不保证） |
| 查出是哪个进程锁着某个文件并结束它（Restart Manager） | 结束受保护进程（系统关键进程、反作弊驱动保护的进程） |
| 汇总近 7/30 天的错误事件、定位蓝屏/崩溃/更新失败 | 解析蓝屏 dump 文件内容（需要调试器与符号） |
| 查看已装补丁、暂停/恢复更新、清理更新下载缓存 | 绕过企业组策略强制安装/屏蔽特定补丁 |
| 测网卡/DNS/网关、ICMP 延迟丢包、TCP 443 连通性、DNS 解析耗时、Wi-Fi 信号、系统代理 | 抓包分析（需要 pcap 驱动） |

针对更新版 Win11 对 PackagedCom 的保护，WinKit 采用「写入 `Shell Extensions\Blocked` + 将 `PackagedCom\Package\...\Class` 登记改名为 `.WinKitDisabled`」两层机制，并在状态列明确标注「已屏蔽·深度」。若包清单读不到（无法确认哪些 COM 类属于右键菜单），屏蔽按钮会被禁用，避免误伤预览器/后台任务等其它壳扩展。

## 运行要求

- Windows 11 x64
- 官方发布为 **win-x64 自包含单 EXE**，已包含 .NET 运行时，无需安装器、解压或另装 Desktop Runtime
- 以普通权限启动（`asInvoker`）；浏览页面不弹提权框，需要管理员的操作会说明原因，可按需点击「以管理员身份重新启动」（见下文「权限模型」）

## 快速开始

1. 从[本仓库 Releases](https://github.com/JourneyHua/WinKit/releases/latest) 下载最新版 `WinKit-v<版本>-win-x64.exe`，放到准备长期保留的位置。
2. 双击下载的 EXE，默认以普通权限启动。若 Windows 显示安全提示，请先核实下载来源，再参考下文的 SmartScreen 说明。
3. 左侧选模块浏览；需要管理员权限时，页面会给出说明。确认要执行对应操作后，再点击「以管理员身份重新启动」。
4. 修改前阅读确认与范围说明；支持快照的操作可点「撤销上一步」，或在「备份与还原」回滚本次会话。PATH 编辑先保留为草稿，点击「应用 PATH 更改」才写入。部分资源管理器设置需重启资源管理器后可见。

## SmartScreen 与下载文件标记

未建立声誉的程序可能触发「Windows 已保护你的电脑」。提示是否出现还受文件声誉、下载来源标记（MOTW）及本机安全策略影响，不能保证每台机器或每次运行的行为相同。参见 [Microsoft Defender SmartScreen 官方说明](https://learn.microsoft.com/en-us/windows/security/operating-system-security/virus-and-threat-protection/microsoft-defender-smartscreen/)。

确认发布来源可信后，如果下载 EXE 的属性页提供「解除锁定」，可用它移除该文件的来源标记；这不等于关闭 Defender，也不保证组织策略或其它安全检测不再提示。

## 单 EXE 与应用更新

- **直接运行**：运行时与原生依赖已打入单个 EXE，无需安装。
- **WinKit 自身更新**：默认在后台最多每 24 小时检查一次本仓库的正式稳定版，可在设置中关闭；左侧「WinKit 更新」可打开更新面板。检查只读取发布信息，点击「下载更新」后才传输 EXE，显示进度并可取消、重试。下载完成核对大小、SHA-256、程序版本和自包含单文件结构。
- **重启并更新**：看过发布说明后，点击「重启并更新」才替换当前程序。助手先就绪再关闭窗口；仅写入原位置确实需要权限时请求 UAC，取消或准备失败会保留当前窗口。成功后保持原文件路径、文件名和原来的使用身份，并清理更新期间的原文件保护副本，不保留长期旧版或提供手动回退。
- **未完成的工作**：有未应用的 PATH 草稿时不能重启更新。点「查看 PATH 更改」返回草稿，应用或舍弃后再更新。应用管理中原有的 winget 与 Scoop 功能完整保留；本仓库不通过这些包管理器发行 WinKit。
- **单文件运行时**：首次启动会由 .NET 将必要的原生组件释放到当前用户的临时缓存，更新也会短暂使用助手与同卷暂存文件；无需手动解压或安装运行时。
- **权限与反馈**：页面内说明按需提权；支持快照的改动显示可撤销反馈，撤销/回滚失败保留记录供重试。忙时限制重复操作与导航，关闭窗口会延迟到当前操作结束，也可取消关闭。
- **残留与还原**：应用和右键菜单的卸载残留在页内展示；备份还原先预览全部目标，确认时重新核对快照内容哈希。
- **PATH 草稿**：用户与系统分别保留未应用更改，刷新、切换作用域不会悄悄丢稿；发现外部更改时先解决冲突。
- **文件工具**：对比结果绑定本次输入范围；重复文件在回收前按扫描指纹再次核验，失败项保留路径和原因。具体操作见下方各模块说明。

## 各模块怎么用

- **全表头点击排序**：所有数据表格（右键菜单、应用管理、常用运行库、驱动管理、注册表体检、备份与还原、事件日志、网络诊断）均支持点击任意列头切换升序 `▲` / 降序 `▼` 排序；软件大小与快照大小按真实字节数排序，安装日期与快照时间按真实时间排序。
- **一键定位注册表 (`regedit`)**：在右键菜单、导航栏固定项、应用管理、注册表体检中，均支持右键菜单或快捷按钮一键打开系统 `regedit.exe` 并自动展开定位到对应注册表项。

### 界面与外观

- **分组导航**：24 个模块按「体检与安全 / 系统设置 / 应用与驱动 / 资源管理器 / 文件与磁盘 / 网络与诊断」分为 6 组，默认只展开当前模块所在的组，点组标题可折叠/展开并记住状态。
- **图标**：每个模块配一个 Segoe Fluent Icons 字形（系统自带、矢量、跟随 DPI），字体缺失时不影响使用。
- **深色模式**：浅色 / 深色 / 跟随系统三档，左下角齿轮按钮切换，所有页面与表格同步换色。实现上所有画刷引用都是 `DynamicResource`，切换时整体替换配色字典——XAML 里的画刷会被 WPF 自动冻结，运行时改 `Color` 会抛异常，所以只能换字典。
- **表格密度**：紧凑（行高 30）/ 舒适（行高 34）两档，默认紧凑。
- **记住窗口状态**：位置、大小、最大化、上次停留的模块都存 `%LOCALAPPDATA%\WinKit\ui.json`；多屏拔插导致窗口跑到屏幕外时自动回落到居中。
- **空状态 / 加载态 / 错误条**：数据为空、正在扫描、扫描失败三种情况各有明确提示，不再是一片空白只靠底部一行灰字。
- **表格布局**：内容列按窗口空间分配宽度，操作列按实际按钮组预留空间，不再用一个固定宽度描述所有页面。可拖动列头边界调整列宽；关键页面的按钮可见性与横向溢出由离屏自检检查。
- **动效**：按下约 65 ms，悬停和选中约 110 ms，页面标题、提示和方向图标约 150 ms，同一条减速曲线。新内容立即可用；不保留会挡住操作的旧画面，不给滚动、列宽、筛选结果、行重排或数字加延迟。关闭 Windows 的「动画效果」或使用高对比度时，立即显示最终状态。
- **操作反馈与忙碌状态**：支持快照的改动会显示含「撤销上一步」的页内反馈。操作进行中会限制重复执行和页面切换；此时关闭窗口会显示「当前操作完成后将关闭窗口」，可点击「取消关闭」。

### 体检与维护

- **一键体检**：把系统概览、磁盘健康、事件日志（近 7 天）、Windows 更新、启动项五个分区的检查结果汇总成一页，给出 0~100 分与 A~D 等级（每项异常扣 8 分、注意扣 3 分，下限 0）。
- **导出报告**：Markdown（给人看，能直接贴到 issue/笔记）与 JSON（给机器比对——配合「文件与文件夹对比」，可以对比上周与本周两次体检的差异）。报告存 `%LOCALAPPDATA%\WinKit\Reports`。
- **定期维护（可选，默认不开启）**：一键注册名为 `WinKit-WeeklyMaintenance` 的 Windows 计划任务，每周日 03:00 以 `WinKit.exe --maintain` 运行：
  - 安全清理默认勾选的临时/缓存目标（**只删存在超过 2 小时的文件**，避免误删其它进程正在用的临时目录）
  - 生成一份体检报告
  - 结果追加到 `%LOCALAPPDATA%\WinKit\Logs\scheduled.log`
  - 下次打开 WinKit 时，如果上次维护失败，状态栏会直接提示，而不是静默烂在日志里
- 任务在界面里可见、可「立即运行」、可一键删除；**删除前先把任务 XML 导出到** `%LOCALAPPDATA%\WinKit\TaskBackups`，需要时可以再导入。
- 注册「以最高权限运行」的任务需要管理员权限，未提权时会明确提示而不是抛英文错误。

### 磁盘健康

- 通过 PowerShell 取 `Get-PhysicalDisk` 与 `Get-StorageReliabilityCounter`：型号、介质类型（SSD/HDD）、健康状态、序列号、**S.M.A.R.T. 预测失败位**、**SSD 磨损度**、温度、通电时长、读写错误计数。
- 各卷单独列出容量与占用，超过 85% 标黄、95% 标红。
- 数据源需要管理员权限；读不到时如实显示「不可用」并给出原因，不猜也不崩。
- 判定逻辑：SMART 预测失败或磨损 ≥90% 判「异常」，磨损 ≥80% 或温度 ≥70 °C 判「注意」。

### 系统还原点

- 列出本机全部还原点（序号、创建时间、说明、类型：应用安装/应用卸载/驱动安装/设置修改/已取消），可直接删除、也可**恢复到这之前的某个还原点**。
- 「创建还原点」用 `Checkpoint-Computer` 手动打点，说明文字可自定义；「开启/关闭系统保护」用 `Enable-/Disable-ComputerRestore`。
- 恢复与关闭保护都有二次确认，提示「会立即重启」「个人文件不会被回退」——这两件事必须让用户知道后再动手。
- 删除走 `SRRemoveRestorePoint`（`srclient.dll`），返回 0 才算成功；读列表走 `Get-CimInstance root/default:SystemRestore`，**两条路径都比 WMI 的 `SystemRestore.Create` 老接口可靠**。
- 读不到时如实说明「需要管理员权限」或「系统保护没开」，不假装有数据。系统保护的频率设置也会显示出来（`SystemRestorePointCreationFrequency`：负数=系统默认 24 小时、0=不限制）。

### 进程管理

- 列出全部进程：进程名、PID、描述、内存占用、线程数、启动时间，支持按名字/描述/公司/路径/PID（纯数字按 PID 精确匹配）过滤，摘要显示进程数与内存合计。
- 「结束进程」与「结束进程树」都有确认框；**不允许结束 WinKit 自己**（否则用户等于自断手脚），结束系统进程会被系统拒绝，如实报错。
- 结束之后会等 3 秒确认进程真的退了：只发出请求不算成功，超时就如实说「已发出结束请求，但 X 在 3 秒内没有退出」。
- 枚举只用 `Process.GetProcesses()` 读 `MainModule`，**不走 WMI**——WMI 查几百个进程慢一个数量级；读不到信息（受保护进程或刚好退出）的那几条跳过并计数，不让整页失败。

### SMART 属性

- 按磁盘列出 **S.M.A.R.T. 原始属性表**：属性 ID、名称、当前值、最差值、阈值、原始值、判定（正常/注意/临界）。走 `MSStorageDriver_FailurePredictData` + `FailurePredictThresholds`，比「磁盘健康」页的汇总结论细一档。
- 判定规则：当前值 ≤ 阈值 → 临界（≤ 阈值一半）或注意；重映射扇区、待映射扇区、无法校正错误、离线不可校正这类属性的原始值只要大于 0 就直接标注意——**这几项非零就是硬盘在说实话**。
- 原始值按属性语义翻译：通电时间换算成小时、温度属性取低字节标 °C、重映射/待映射标个数、寿命类属性换算成「剩余 N%」，其余原样显示十进制。
- 「导出 CSV」写到 `%LOCALAPPDATA%\WinKit\Exports\`，带 UTF-8 BOM（否则 Excel 打开中文乱码），写完可直接打开所在目录。
- 只有控制器愿意透传的盘才读得到：USB 外置盘、部分 RAID/虚拟盘会明确显示「这块盘的控制器没有透传 SMART 原始数据，只能看『磁盘健康』页的汇总结论」。

### 环境变量与 PATH

- 列出当前用户与系统两套环境变量，支持搜索、新增、编辑、删除；写入走快照，可撤销。
- **PATH 可视化编辑**：每条路径单独一行并标记「目录不存在」，支持添加、移除、上移/下移。编辑仅修改草稿，点击「应用 PATH 更改」并确认后才写入。
- **用户/系统分别留稿**：本次运行中，刷新列表、更新其它变量或切换作用域都会保留未应用的 PATH 草稿；「放弃草稿」需确认，只丢弃当前作用域的草稿并读取最新值。
- **外部冲突不覆盖**：应用确认前后都会比对读取时的原始 PATH；若已被其它程序更改，保留草稿、禁用应用，并提示先放弃草稿读取最新值后重新编辑。
- PATH 只改字符串，不删除目录；写入时去重、去空、保留其余顺序与原有值类型。系统 PATH 的写入需要管理员权限。
- 写入后广播环境变量变更；新进程可读取新值，已经运行的程序通常需要重启。

### 系统概览（只读）

- 四张卡片：**系统**（版本/内部版本/计算机名/当前用户/安装日期/已运行时长）、**硬件**（CPU 型号与逻辑处理器数、内存总量与占用、显卡）、**存储**（每个卷的容量、已用百分比、可用空间）、**健康与安全**（待重启、Defender、防火墙、安全启动）。
- 全部走注册表、`Environment` 与 Win32（`GlobalMemoryStatusEx`），**不联网、不写任何东西**，打开即用。
- 占用超过 85% 标黄、95% 标红；待重启/防护关闭/安全启动未开启会标黄，方便一眼看出该处理什么。

### 文件占用解锁

- 删除或移动文件时提示“文件正在被使用”，在这里粘贴路径（或点「选择文件」）→「查询占用」，用系统自带的 **Restart Manager** 查出占用进程，显示 PID、类型（桌面程序/后台服务/资源管理器）、启动时间与程序路径。
- 支持单个「结束」或「结束全部占用进程」，结束前会二次确认；系统关键进程（PID 0/4）不可结束。
- 若运行环境连不上 Restart Manager 服务（受限会话/沙箱里会返回错误码 29），会自动退回到「已加载模块扫描」：至少能定位把该 DLL/EXE 装进进程的程序，并额外做一次独占打开测试，告诉你文件到底有没有被锁。

### 文件与文件夹对比

- 左右各选一个**文件夹**（递归或只看顶层），或选同类型的**两个文件**，点「开始对比」。
- 默认按「大小 + 最后写入时间」比较，几万个文件也很快；勾选「比对内容哈希」后，对参数完全相同的文件再算 SHA-256，能识别**大小和时间都相同但内容被改过**的情况。
- 结果按差异分类：内容不同、仅左侧、仅右侧、左侧较新、右侧较新；「只看差异」可过滤掉相同项。
- **结果绑定本次范围**：对比中锁定路径与比较选项；更改路径、递归或哈希选项后清空旧结果。每行定位/复制只使用产出该结果时捕获的路径，不会把旧行套到新输入上。
- 每行可一键定位到左侧/右侧资源管理器并选中，或复制路径。
- 典型用途：校验备份是否完整、对比两份配置目录、确认「更新后的程序目录」到底动了哪些文件。

### 重复文件检测

- 添加扫描目录（「加入常用文件夹」可加入图片/视频/音乐/文档/下载），可设最小体积（如 `500 KB` / `1 MB` / `2 GB`）及是否包含隐藏/系统文件。
- **三级校验**：按大小分组 → 头部 64KB 哈希 → 全文件 SHA-256，只有三级都相同才列为重复。
- 按「可节省空间」排序，每组显示份数、单份体积与可省空间；可「保留首份，其余移入回收站」，也可处理单个副本。
- **回收前复核**：按扫描记录的大小和完整 SHA-256 核验保留副本及每个目标。保留副本缺失、变化或无法读取/锁定时整批不清理；目标核验或回收失败会逐项列出路径与原因，其它通过核验的目标可继续。内容已变时请重新扫描。
- 清理使用系统回收站；是否还能恢复取决于回收站中是否仍保留文件，不承诺永久可还原。
- 后台扫描可取消；扫描与清理忙时锁定范围、条件和再次执行入口。结果使用启动时捕获的范围，范围变化后不沿用旧扫描结果。

### 默认打开方式

- 列出本机所有扩展名（实测约 700 个）及其关联程序：扩展名、来源（用户指定 / 系统默认）、关联程序名、ProgID、打开命令。
- 支持按扩展名 / ProgID / 程序名搜索，可只看「用户指定」的项。
- **为什么不能直接改**：Windows 8 起 `UserChoice` 带哈希签名，直接写注册表会被系统判定篡改并自动重置，所以本工具不硬改关联，只做三件事：
  1. **更改**：跳到系统「默认应用」里该扩展名的设置页（官方支持的唯一可靠路径）；
  2. **打开方式**：调起系统的「打开方式」对话框，等价于资源管理器右键；
  3. **清理失效关联**：只处理「打开命令指向的 exe 已不存在」的扩展名，且只删 HKCU 下的默认值，带快照可撤销。

### 事件日志诊断

- 拉取 `System` 与 `Application` 两个日志里近 **7 天 / 30 天** 的「错误 + 严重」事件，按 **来源 + 事件 ID + 级别** 归并成一行，显示出现次数、首次/最后时间与示例数据。
- 自动分类：蓝屏/意外关机、应用崩溃、更新失败、磁盘/存储、电源/启动、网络、安全、服务启动失败、证书/加密、COM 组件、性能计数器。
- 支持复制单条详情、一键打开系统「事件查看器」。
- 实现上调用系统自带 `wevtutil qe ... /f:xml`，不引入 EventLog NuGet 包，普通用户即可读取（Security 日志除外）。

### Windows 更新

- **已安装补丁**：优先读 CBS 包仓库（`Component Based Servicing\Packages`，Win11 的补丁登记在这里），再兜底读 `Uninstall` 登记项；显示 KB 编号、类别、安装时间。全程本地读取，不联网。
- **暂停 / 恢复更新**：写 USO 的 `PauseUpdatesStartTime` / `PauseUpdatesExpiryTime`，提供 7 / 14 / 35 天三档，改前自动快照，随时可撤销。
- **清理更新下载缓存**：临时停止 `wuauserv` → 清空 `C:\Windows\SoftwareDistribution\Download` → 重新启动服务，报告删除文件数与释放空间。
- 顶部状态行显示暂停状态、服务启动类型、缓存体积、是否待重启；检测到组策略配置时会提示「部分开关可能被策略接管」。

### 网络诊断

- **网卡与 DNS**：列出有地址或网关的网卡（自动过滤 QoS/WFP 等过滤驱动伪接口），显示类型、状态、IPv4、网关、DNS。
- **延迟与丢包（ICMP）**：对网关、223.5.5.5、8.8.8.8 各发 4 个包，显示平均/最小/最大延迟与丢包数。
- **外网连通（TCP 443）**：对百度/微软/GitHub 做 TCP 连接测试——ICMP 常被防火墙或代理拦掉，TCP 结果更可靠。
- **DNS 解析耗时**：解析 3 个常见域名并计时，超过 500 ms 标黄。
- **Wi-Fi 与系统代理**：解析 `netsh wlan show interfaces`（SSID/状态/信号/协议/信道/速率，需要管理员权限）与 `Internet Settings` 里的代理开关、服务器、PAC 地址、例外。
- 快捷操作：刷新 DNS 缓存、重置 Winsock、重置 TCP/IP、打开网络设置、打开 hosts 文件。

### 右键菜单

- **全局切换「默认直接展开经典菜单」**：顶栏右侧提供一键开关（控制 `HKCU\Software\Classes\CLSID\{86ca1aa0-34aa-4e8b-a509-50c905bae2a2}\InprocServer32`），开启并重启资源管理器后，右键直接弹出完整经典菜单，无需再点「显示更多选项」；同样支持快照撤销。
- **一级菜单（右键直接看到的那层）**：不点「显示更多选项」时弹出的紧凑菜单。
  - **数据源是包清单**（`AppxManifest.xml` 里的 `windows.fileExplorerContextMenus`），不是注册表里的 COM 类清单。后者只说明"这个包注册了哪些 COM 类"，会把背景任务、预览器全混进来——这正是之前"显示中却看不到"的原因。
  - 清单里 `<ItemType Type="*">` / `Directory` / `Directory\Background` / `Drive` 就是作用域，左侧域树据此分组。
  - **驱动器会继承「文件夹」作用域的项**：VS Code、PowerRename 只声明了 `Directory`，却照样出现在驱动器右键里。所以驱动器分组 = 声明 `Drive` 的 + 被继承的文件夹项，后者在「继承」列标注。
  - 读不到清单的包单独归入「作用域未确认」并置灰，不假装它一定在菜单里。
  - **两层屏蔽**：勾掉或点「屏蔽」= ① 把该软件所有 `IExplorerCommand` 的 CLSID 写进 `Shell Extensions\Blocked`；② 遍历该软件合并的全部版本包，将 `PackagedCom\Package\...\Class\{CLSID}` 改名为 `.WinKitDisabled`（状态列显示「已屏蔽·深度」）。
  - 行内「卸载」调用软件自己的卸载程序；卸载后每 3 秒轮询、最多 10 分钟，页内残留卡显示等待、结果或失败。可主动点「复查残留」，按需「定位注册表」或「打开残留目录」；「重新扫描」用于刷新菜单列表，不代替残留复查。
  - 内置项（打开、复制、粘贴、重命名、共享、发送到、属性、显示更多选项）由 Windows 硬编码，无可移除接口。
- **经典菜单（显示更多选项）**：8 个位置域——文件、文件夹、文件夹空白处、驱动器、桌面空白处、库、发送到、新建。
  - 勾选框 = 启用/禁用（`LegacyDisable` 或屏蔽列表，完全可逆）
  - 「改名」= 写 `MUIVerb`，只改显示名
  - 「复制路径」或表格行右键菜单 = 一键复制注册表路径或命令路径
  - 「删除」= 真删注册表项或发送到快捷方式，但删前自动快照，可撤销
  - 默认视图是「仅第三方 + 高频四域」，减少系统内置项的干扰
- **发送到**：本质是快捷方式文件，禁用 = 移到 `%APPDATA%\WinKit\SendToBackup`；启用、禁用、删除均包含轻量文件快照，可通过「撤销上一步」或「备份与还原」恢复。
- **新建**：禁用 = 把 `ShellNew` 键改名，数据保留

### 此电脑

- **用户文件夹**：3D 对象、桌面、下载、文档、图片、音乐、视频（ThisPCPolicy）
- **系统节点**：控制面板、网络、第三方注册的命名空间（WPS 云盘、腾讯应用宝等）。
  - 带 `HiddenByDefault` 的系统节点：隐藏 = 把该值置 1（**不删键**），恢复 = 置 0，零损失。
  - 第三方节点没有该值：隐藏 = 删键，删前会把整键内容备份到 `%LOCALAPPDATA%\WinKit\NodeBackups`；恢复时用这份快照原样写回，**保留原默认值（`CLSID_xxx` 名称引用）与 `HiddenByDefault`**，不会重建成裸 GUID。
  - 被 WinKit 隐藏过的节点会继续列在列表里（标记「已被 WinKit 隐藏」），随时可以勾回来。
- **驱动器**：隐藏 = 写 `NoDrives` 位掩码。只影响资源管理器显示，不动盘符和数据

### 导航栏

- **导航栏固定项（软件节点）**：iCloud Photos、WPS 云盘、腾讯应用宝文件管理、小米云盘、OneDrive 这类软件自己钉在"此电脑"下面的节点。
  原理是 CLSID 上的 `System.IsPinnedToNameSpaceTree`，关掉 = 把它改成 0，**不删注册表项、不卸载软件**，勾回来即恢复。改完需要重启资源管理器看效果。
- **顽固节点（会自动重建）**：有些软件（典型是 WPS 云盘）每次启动都换一个新 GUID 重新钉上去，所以按单个 ID 关永远关不完。
  这里按显示名把同族 GUID 归组，一次性删掉全部注册项（此电脑 + 导航栏），并能定位/结束重建它的后台进程（如 `wpscloudsvr.exe`）。
  注意：结束进程只影响该软件的后台组件，别去结束你自己正在用的主程序。
- **快速访问固定项**：可增（选文件夹）、删（取消固定）、调顺序（「应用新顺序」会先全部取消再按列表重钉，过程几秒）
  - 顺序重建在后台线程执行，界面不会假死；若有项目未能恢复固定，会弹出清单告诉你具体哪几个需要手动重钉，而不是默默当作成功。
- 「最近使用」的条目只能读，取消固定请用资源管理器右键
- 四个导航窗格开关直接写 `Explorer\Advanced`

### 任务栏与通知区域

顶部「导航栏 / 任务栏」两个 chip 切换。

- **任务栏固定项**：列出 `%APPDATA%\Microsoft\Internet Explorer\Quick Launch\User Pinned\TaskBar` 下的 `.lnk`，可启动、定位、**取消固定**。
  - 取消固定走 shell verb（按名字匹配 `unpinfromtaskbar` / `taskbarunpin`），并且**以快捷方式是否真的消失为准**——shell verb 的返回值在部分系统上不可靠，光看返回值会假报成功。
  - **本模块不提供「固定到任务栏」与顺序调整**：Windows 11 已经取消了「固定到任务栏」的公开入口（开始菜单快捷方式、`shell:AppsFolder` 里的应用，右键都只有「固定到开始屏幕」）。既然无法新增固定项，也就无从重排。
  - 「资源管理器」「任务管理器」这类是 CLSID 链接（`.lnk` 没有 `TargetPath`），标记为「系统内置」而不是「失效」，不会被误判成死链。
- **通知区域（托盘）图标**：读 `HKCU\Control Panel\NotifyIconSettings`，勾选框控制是否常驻托盘（写 `IsPromoted`），并广播 `WM_SETTINGCHANGE("TraySettings")` 让系统立即生效。
  - 每条记录的路径常写成 KnownFolder GUID 前缀（如 `{6D809377-...}\Python314\python.exe`），必须先经 `SHGetKnownFolderPath` 解析再判断存在性，否则会把大量正常图标误报成失效。
  - 失效判定是**三态**：存在 / 失效 / 判不了。像 `C:\Program Files\WindowsApps` 这种非管理员不可枚举的目录一律算「判不了」，不会被「折叠失效项」误伤。
  - 「折叠全部失效项」只把失效且当前常驻的记录置为不常驻，**不删注册表项**；确实想清干净再用「删除失效记录」（走快照，可撤销）。
  - Scoop 每次升级都会留下一条指向旧版本目录的死记录，长期会攒出十几条噪音，这是本页最典型的清理场景。

### 应用管理（卸载、更新与常用运行库体检）

- **全量应用列表**：汇总本机已安装的**传统桌面软件**（注册表 `Uninstall`）、**Microsoft Store / MSIX 打包应用**与 **Scoop 包**，支持按「全部 / 桌面软件 / 商店与打包 / Scoop 包 / 仅看可更新」筛选与关键词搜索，展示版本、类型、体积、安装日期与安装位置。
- **Scoop 包集成**：直接读本地目录，**离线**即可判断可升级版本——已装版本来自 `apps\<name>\current\`（`scoop-manifest.json` 与旧版 `manifest.json` 两种文件名都支持），可升级版本来自 `buckets\<bucket>\bucket\<name>.json`。只有真正执行「更新 / 卸载」时才调用 `scoop` 命令。读不到版本（如 `scoop` 自身是自举安装）会如实标注「版本未知」，不虚报可升级。
- **软件卸载与残留清理**：
  - 传统桌面软件调起官方自带卸载程序并自动监测卸载完成；商店与打包应用通过系统接口直接卸载。
  - 卸载完成后扫描失效的卸载注册项与残留 COM 类（CLSID），在页内残留卡呈现等待、结果和失败，不再连续弹出清理/打开目录询问。
  - 「清理注册表残留…」会先重新扫描、确认后通过快照清理；「打开残留目录」仅定位目录，不擅自删除文件。可主动复查残留；「重新扫描」仍只刷新应用列表。
- **卸载残留清理（第 4 个子视图）**：针对「卸载程序已经跑完、但机器上还留着一堆东西」这种情况。
  - **拖入文件夹或快捷方式**即可识别：能匹配到卸载登记就直接给「运行卸载程序」；匹配不到就在目录里找候选卸载器（`SUPUninstall.exe`、`PPUninstallerUi.exe`、`Netbird_uninstall.exe` 这种命名极不统一，只按名字模糊匹配且**只认 `.exe`**——`uninstall.dat`、`Uninstall.lst` 这类名字像卸载器的非可执行文件必须排除）；没有找到卸载程序时，若软件已经卸载，可以扫描残留。
  - 拖放能在**提权进程**里生效，靠的是启动时给窗口放行 UIPI 的三个拖放消息（`WM_DROPFILES` / `WM_COPYDATA` / `WM_COPYGLOBALDATA`，见 `Native.AllowDragDropFromLowerIntegrity`）。**这不是可选项**：当 WinKit 以管理员身份运行、资源管理器为普通权限时，系统默认会把这些消息跨完整性级别静默丢掉，表现就是「拖进来毫无反应，也没有任何报错」。如果被安全软件或组策略又拦了一道，就用旁边的「**粘贴路径**」按钮（资源管理器里 `Ctrl+C` 复制文件夹或快捷方式，回来点它），效果与拖入相同。
  - **残留扫描**覆盖六类：目录、快捷方式（开始菜单/桌面/任务栏/快速启动）、服务（`ImagePath`）、计划任务（含 XML 内容里的路径）、启动项（4 个 Run/RunOnce 键）、文件关联（`UserChoice` 的 ProgId → `open\command`）。
  - 「引用目标路径」或「名称相似」只是关联线索，不代表可以安全删除。默认不勾选任何项目；计划任务、文件关联和可能包含当前安装目录的上级文件夹只供查看。
  - 先用常规扫描。没有找到预期结果时可试「深度扫描」，扫描过程中可停止。扫描不会沿重解析点进入其他目录。
  - 确认后，文件夹和快捷方式请求移入回收站，仍在回收站的项目可在那里还原；注册表设置先备份再移除，可在 WinKit 撤销。两类还原是独立的。
  - 「处理整个文件夹」默认收起，需输入文件夹名确认。这不是卸载；若 Windows 提示永久删除，应取消。处理结果会在页面反馈，记录保存在 `%LOCALAPPDATA%\WinKit\UninstallLogs\`。
- **软件更新（基于 `winget` 与 `scoop`）**：
  - 点「检查更新」同时比对两类来源：`winget`（调用 Windows 11 内置包管理器）与 `scoop`（读本地 bucket 清单，离线）。列表中直观显示 `当前版本 → 最新版本`。

| 分类 | 内容 | 可清理 |
|---|---|---|
| 启动项 | Run / RunOnce / Winlogon | 指向的文件不存在时 |
| 右键菜单 | 各域条目汇总，管理请到右键菜单页 | 否 |

### 备份与还原

- 查看本次会话与历史快照；点「详情」或「还原…」先打开页内预览，再选择是否确认还原。
- 预览逐项列出完整注册表路径与视图、文件路径，以及覆盖/删除影响；注册表还原会移除备份后新增的值和子键，确认前请完整核对目标。
- 确认时重新读取快照并比对预览时的 SHA-256；内容已变则拒绝执行，需重新预览。涉及 HKLM 的备份需要管理员权限。
- 撤销、回滚或还原失败会显示原因；未完成的撤销/回滚记录会保留供重试。历史备份成功还原前也会捕获当前状态，支持再撤销该次还原。

## 安全机制

- 支持快照的写操作会先把**受影响的注册表键**（含子键、值、类型）及**发送到快捷方式文件**存成 JSON 快照：`%LOCALAPPDATA%\WinKit\Backups`
- 只存改动涉及的部分，几十 KB 一份，保留最近 50 份
- 「撤销上一步」在完整还原成功后移除对应会话记录并尝试清理备份；「回滚本次会话」按相反顺序执行，遇到失败停止并保留未完成记录供重试
- 还原是**差量写回**：先删掉快照里没有的值/子键，再写回快照中的值，不会整树删除重建，键的安全描述符保持不动
- **快照不完整时拒绝破坏性还原**：子键数超过上限（20000）会标记 `Truncated`，还原直接报错，而不是删掉没记下来的子树
- **读取被拒的键标记 `CaptureFailed`**：不会把「没权限读」误判成「原本不存在」，撤销时不会去删一个真实存在的键
- 快照里的注册表根只接受 `HKCU` / `HKLM`，手改或损坏的备份文件会被拒绝，不会落到系统区
- **注册表视图（32/64 位）随路径一起快照**：`RegPath` 带 `View`，还原时写回同一个视图，32 位登记不会被写到 64 位侧
- 快照支持的写操作异常时尝试自动回滚；失败项如实列出，自动回滚也未完成时保留原记录，便于排除占用或补足权限后重试
- 本地枚举与快照不需要联网；网络诊断会主动发包，检查/下载安装软件、运行库或驱动更新时也可能访问相应来源

## 开发

SDK 装在用户目录（避免 UAC）：`%USERPROFILE%\dotnet-sdk\dotnet.exe`，或直接用你机器上任意 `dotnet`（.NET 10 SDK）。

```bash
# 编译
dotnet build WinKit.slnx

# 发布（win-x64 自包含单 EXE；项目仅在 publish 时启用）
dotnet publish src/WinKit/WinKit.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=embedded -p:PublishTrimmed=false -p:PublishAot=false -o dist/publish

# 生成带版本名的 EXE 和配套更新元数据（Windows）
.\build.cmd

# 界面自检：用发布的单 EXE 渲染各模块，并短时打开窗口验证真实交互
dist\WinKit-v1.13.0-win-x64.exe --smoke C:\temp\smoke

# 动效专项：真实 WPF 窗口、普通/减少动态效果、6000 行滚动、窄/宽和浅/深截图
# motion.log 的帧间隔是 WPF 渲染回调，不是显示器实际呈现间隔。
dist\WinKit-v1.13.0-win-x64.exe --motion-smoke C:\temp\smoke-motion

# 只读探测：枚举全部菜单项/节点/驱动器/快速访问，落一份报告
dotnet run --project tools/Probe -- report.txt

# 自测：快照/撤销/还原保真/32-64 视图、解析器、分类器与交互状态等；用例数随版本变化
dotnet run --project tools/Probe -- --selftest

# 更新协议与下载：使用已发布的自包含 EXE 作为只读夹具
dotnet run --project tools/UpdateProbe -- --fixture dist/publish/WinKit.exe

# Windows 文件替换事务：仅写入探针自己的临时目录，不执行夹具
dotnet run --project tools/UpdateInstallerProbe -- --fixture dist/publish/WinKit.exe

# 无人值守维护（计划任务用的就是这条命令）：清理 + 体检报告 + 写日志
WinKit.exe --maintain
```

`build.cmd` 在 `dist/` 生成 `WinKit-v<版本>-win-x64.exe` 与 `WinKit-v<版本>-win-x64.update.json`。正式 Release 和内置更新继续使用这两个文件；普通 solution build 与 Probe 仍使用框架依赖构建，避免项目引用受自包含设置影响。

### 备用构建：压缩自包含版和不带运行时版

在装有 .NET 10 SDK、x64 Desktop Runtime 和 PowerShell 7.4+ 的 Windows 上，运行 `pwsh -File ./build-variants.ps1`。脚本从同一份源码构建两个单文件 EXE，在实际窗口里跑动效自检，并打印精确字节数和 SHA-256；默认输出到 `dist/variants/`。同版本重复构建可用 `-OutputDirectory` 指定新目录，不会覆盖已有 EXE。

| 文件名后缀 | 什么时候选 |
| --- | --- |
| `-win-x64-compressed.exe` | 想减小下载体积，又不想另装任何运行时。仍是自包含 EXE。 |
| `-win-x64-framework-dependent.exe` | 电脑已经有 [.NET 10 Desktop Runtime（Windows x64）](https://dotnet.microsoft.com/download/dotnet/10.0)，希望下载更小的 EXE。仅装普通 .NET Runtime 不够。 |

`package-variants` 工作流将两份 EXE 分别上传为 Actions 构建产物（下载需登录 GitHub，下载后从 Actions 的 ZIP 中取出 EXE）。它们不是正式更新资产，不生成 `.update.json`；若通过应用内置更新升级，下载的仍是正式 Release 的自包含版，不会沿用备用构建格式。若希望保留所选格式，请手动下载对应的新构建。

更新元数据使用 UTF-8 JSON，固定字段为 `schemaVersion: 1`、字符串 `version`（如 `1.12.0`）、`rid: "win-x64"`、`fileName`（完整 EXE 文件名）、`sha256`（64 位十六进制 SHA-256）与 `size`（64 位整数，EXE 字节数）。哈希和大小都由最终上传的 EXE 计算，发布说明由 GitHub Release 正文提供。标签必须为 `v<项目版本>`，CI 会核对标签、项目版本以及 EXE 的 ProductVersion/FileVersion，并拒绝包含额外散件的发布目录。

自测会在低完整性级别（受限令牌/沙箱）下自动跳过写入类用例并标注 `SKIP`，只读用例照常执行；
要覆盖快照写入与撤销，请在正常桌面会话（中完整性以上）运行。

### CI 质量门槛

GitHub Actions 对 `master` 推送、面向 `master` 的 pull request、`v*` 标签及手动触发运行构建与检查；只有标签触发创建 Release。以工作流中的断言和本次运行日志为准，以下不是当前工作树已通过测试的声明。

1. **服务层自测**：`tools/Probe --selftest` 返回非零即失败；用例数随代码变化，不固定为某个总数。`--selftest` 属于 Probe，不是 `WinKit.exe` 的参数。
2. **界面离屏自检**：直接运行 `asInvoker`、win-x64 自包含单 EXE；通过自检的同一个 EXE 才用于 Release。检查进程退出码、`SMOKE OK`、至少 24 个模块渲染及关键模块数据、空态/错误原因。另检查列宽拖动、子视图隐藏、应用操作列未挤压或横向溢出、拖放放行、非模态导航/可撤销反馈，以及 14 页错误提示均不遮挡操作按钮。
3. **更新协议与替换事务**：更新探针检查正式版筛选、来源及重定向限制、24 小时节流、流式进度、取消/失败清理、版本与自包含单文件校验，并拒绝同版本的框架依赖 EXE；事务探针验证原路径替换、占用、取消、硬链接/目录重解析点防护、失败时保留原文件与成功后的临时保护清理。
4. **发布清单核对**：直接读取 exe 中嵌入的清单，要求 `level="asInvoker"`，拒绝 `level="requireAdministrator"`；这用于验证启动权限模型，不用于保证 SmartScreen 行为。
5. **公开包真实更新**：标签发行完成后，在独立 Windows job 中运行低版本单 EXE 探针，通过生产服务从本仓库正式 Release 下载新版，完成助手就绪、旧进程退出、同路径替换和新 GUI 启动；核对 SHA-256、版本、用户 SID、完整性级别、更新成功提示以及临时保护清理。探针仅在自己创建的 GUID 临时目录运行，不替换用户已有程序。

可视树/状态断言的常见日志：

- `ux-motion` / `ux-motion-shell`：检查动效可打断、减少动态效果时立即更新，验证 6,000 行仍按需绘制、窄/宽主窗口的导航及设置弹层可用。
- `columnresize: ... result=OK`：列头拖动手柄存在且允许改宽。
- `uninstall-hidden: ... visible=False` / `uninstall-view-off: ... visible=False`：卸载残留子视图在未激活及切走后均隐藏。
- `columns-apps: viewport=W total=T hscroll=no`：应用列表未横向溢出；同时按当前声明宽度（应用操作列为 274）检查实际宽度，避免按钮被挤掉。
- `dragdrop: error=0 viewAllowDrop=True`：窗口允许相应拖放消息；受限沙箱可能拒绝，不能把它当作所有运行环境都已验证。
- `restore: ... result=OK` / `smart: ... result=OK`：有数据，或明确解释权限/数据源不可用的原因。
- `elevation: ... navigation=nonmodal` / `ux-interactions: ... result=OK`：浏览走正常的非模态导航路径，并检查权限说明与可撤销反馈状态。
- `ux-backup` / `ux-path` / `ux-diff` / `ux-close`：分别验证完整恢复预览与内容变化拒绝、分作用域草稿和冲突保留、结果与比较范围绑定，以及操作完成后安全关闭。
- `ux-update: ... result=OK`：在真实更新面板操作按钮，验证手动检查失败重试、更新说明、下载取消/重试/校验、操作忙碌保护、助手就绪后才允许关闭，以及 PATH 草稿丢弃提醒；网络边界使用隔离夹具。
- `ux-errors: pages=14 buttons=unobstructed result=OK`：逐页显示真实错误提示，检查其不遮挡任何可见操作按钮，并保留截图。
- `theme: ... visual=True result=OK`：在同一真实窗口验证浅色/深色背景与已创建文本的前景同步切换。

失败时可查看上传的 `smoke-log` artifact，其中包括 `smoke-out/smoke.log`、各模块及错误状态的 PNG 截图，以及标准输出/错误；权限相关写入与真实桌面操作仍需在相应桌面权限下验证。

### 权限模型（asInvoker + 按需提权）

主清单 `src/WinKit/app.manifest` 声明 `asInvoker`，默认沿用启动进程的权限。普通权限启动时不因浏览页面而请求 UAC，也不会在每次进入模块时弹提权确认。

- 含受限操作的页面会显示非模态权限说明与「以管理员身份重新启动」按钮；可先浏览，再按需重新启动。
- 需要管理员的操作在入口处检查权限并给出下一步说明；用户级设置与只读操作不统一要求管理员。点击重新启动后，由 Windows 处理 UAC。
- 自检与正常运行共用同一条非模态导航路径，不再使用单独的提权弹框开关。无人值守的 `--maintain` 不会自行取得管理员权限；需要权限时应由计划任务或启动方式提供。
- 正在执行操作时会限制导航及重复执行；关闭请求会等当前操作结束，避免在写入或恢复过程中直接退出。

修改清单后应重新生成 apphost，并核对嵌入的 `level="asInvoker"` 属性。权限清单与 SmartScreen 声誉检查是不同机制，不能据此承诺没有安全提示。

## 已知限制

1. 一级菜单的 PackagedCom 项采用 `Shell Extensions\Blocked` + `PackagedCom\Package\...\Class` 改名两层屏蔽；若应用更新版本，Windows 会重新注册新版本的包，届时重新屏蔽一次即可
2. 快速访问排序靠「全部取消后重钉」，期间列表会短暂清空
3. `NoDrives` 写完后资源管理器要重启才会刷新显示（「此电脑」页有一键重启资源管理器）；写的是策略键，个别系统还要注销才彻底生效
4. 驱动器隐藏只作用于当前用户
5. 文件占用解锁依赖 Restart Manager 服务；在受限会话/沙箱里会退回到「已加载模块扫描」，只能定位 DLL/EXE 类占用
6. 事件日志只读 `System` / `Application`，`Security` 日志需要额外权限，未纳入
7. 网络诊断会主动发包；软件/运行库/驱动的检查更新、下载和安装也可能需要网络或受企业策略限制，本地枚举与快照不依赖这些在线来源
8. **任务栏只能取消固定，不能固定、不能排序**：Windows 11 取消了「固定到任务栏」的公开入口（开始菜单快捷方式与 `shell:AppsFolder` 里的应用，右键都只有「固定到开始屏幕」），没有固定入口也就无从重排
9. 取消固定走 shell verb，但**成败只看快捷方式是否真的消失**（监听固定项目录的文件变化，最长等 1.5 秒），不看返回值——verb 的返回值在部分系统上不可靠
10. 通知区域图标只能改显隐（`IsPromoted`），**不能调顺序**：顺序由系统内部的 `UIOrderList` 哈希决定，算法未公开
11. 卸载残留扫描是启发式的：完全同名判「确定」，只包含软件名的判「可能」。发布者名相同（如 `The Quark Authors`）、缓存目录、第三方工具里出现的同名片段都会落到「可能」一栏，需要人工勾选
12. 默认扫描深度 3 层（约 1.4 万个目录、4 秒左右）；装得很深的残留（`scoop\persist\<app>` 这类）必须用「深度扫描」，那是递归全扫，耗时按分钟计
13. 文件关联残留只提示不清理：`UserChoice` 带哈希签名，删了会被系统判定篡改并自动重置
14. 拖放依赖 UIPI 放行生效；若第三方安全软件/组策略额外拦截跨完整性级别的拖放，就改用「粘贴路径」按钮，功能等价
15. 系统还原点管理只调用 `SRClient`/`WMI` 的公开接口：创建、列出、删除、恢复到本机已有还原点。**不能跨机器、不能恢复单个文件**，且必须开着「系统保护」才有还原点可用
16. 进程管理只做「看 + 结束」：线程、句柄、模块级细节不做；结束系统进程会被拒绝或导致界面短暂卡顿，属正常
17. SMART 属性依赖硬盘控制器透传：USB 外置盘、部分 RAID/虚拟盘读不到，只能在基准里显示「不支持」
18. 普通权限可浏览页面并执行允许的用户级操作；需要管理员的系统操作会给出权限说明，点击「以管理员身份重新启动」后由 Windows 处理 UAC。浏览页面本身不弹模态提权确认（见上一节「权限模型」）
